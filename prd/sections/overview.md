# Product Summary

<!-- STUB -->

Structure from PDP-08 rev A §4.1. Summarize the product so the PRD can be understood without
reading the Product Concept Document: what it is, who it serves, and the operating context it
is designed for. Keep it concise and product-facing — enough context to interpret the
requirements that follow, without duplicating the deeper treatment of markets, use cases,
release phasing, or operating conditions addressed later. Plain, customer-oriented language;
no architecture, subsystem descriptions, or workflow logic. Recommended length: 4–6 sentences.

| Item | Description |
|---|---|
| Product name / working name | [Insert product name.] |
| Product definition | [What the product comprises — platform, autonomy package, operator interface, and any productized supporting elements inside the product boundary.] |
| Primary job(s) performed | [High-level use case categories only.] |
| Primary beneficiaries | [Customer / user types that benefit most directly.] |
| Why it matters | [Primary value proposition in outcome terms — productivity, labor leverage, safety, consistency, schedule predictability, data quality.] |
| Boundary notes | [Important product-boundary decisions — e.g. whether support equipment, operator stations, or site infrastructure are part of the product for this PRD.] |
